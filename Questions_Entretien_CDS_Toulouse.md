## V. Questions Techniques Approfondies

### 1. Expliquez l'architecture d'une application React moderne.
**Réponse optimisée CDS :**
> "Voici l'architecture que j'utilise pour mes projets React :
>
> ```
> /src
>   /components
>     /ui           - Composants de base (Button, Input, Modal)
>     /features     - Composants métier
>     /layouts      - Layouts de page
>   /hooks          - Custom hooks réutilisables
>   /context        - Providers React Context
>   /services       - API calls et logique externe
>   /types          - Interfaces TypeScript
>   /utils          - Fonctions utilitaires
> ```
>
> **Patterns utilisés :**
> - **Composition** : Composants petits et composables
> - **Custom hooks** : Encapsulation de la logique réutilisable
> - **Render props/HOCs** : Pour les fonctionnalités transverses
> - **Error boundaries** : Gestion gracieuse des erreurs"

### 2. Comment gérez-vous l'état dans une application React ?
**Réponse optimisée CDS :**
> "Je choisis la solution adaptée à la complexité :
>
> **État local (useState) :**
> - Pour les composants isolés
> - Formulaires simples
>
> **Context API :**
> - État partagé entre plusieurs composants
> - Thème, authentification, préférences
>
> ```typescript
> // Exemple de mon projet Mistral AI
> const ChatStateContext = createContext<ChatState>(null);
>
> const useChatConversation = () => {
>   const [messages, setMessages] = useState<Message[]>([]);
>   const addMessage = useCallback((msg) => {
>     setMessages(prev => [...prev, msg]);
>   }, []);
>   return { messages, addMessage };
> };
> ```
>
> **Zustand/Redux Toolkit :**
> - Applications complexes avec beaucoup d'état global"

### 3. Comment travaillez-vous avec Git et GitHub ?
**Réponse optimisée CDS :**
> "Git est au cœur de mon workflow quotidien :
>
> **Workflow :**
> 1. Créer une branche feature : `git checkout -b feature/nom`
> 2. Commits atomiques avec messages clairs
> 3. Push et création de Pull Request
> 4. Code review par les pairs
> 5. Merge après validation
>
> **CI/CD avec GitHub Actions :**
> - Tests automatiques sur chaque PR
> - Linting et formatage (ESLint, Prettier)
> - Build et déploiement automatisés
>
> **Certification :** GitHub Actions (GH-200)"
